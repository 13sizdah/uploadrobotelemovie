# ربات تبدیل فایل تلگرام به لینک دانلود

ربات انواع فایل و رسانه ارسالی در تلگرام را دریافت می‌کند، روی دیسک سرور نگه می‌دارد، یک لینک تصادفی اختصاصی می‌سازد و پس از زمان تعیین‌شده فایل را خودکار حذف می‌کند.

## امکانات

- لینک غیرقابل حدس با توکن تصادفی ۲۵۶ بیتی
- صفحه واسط بررسی مشخصات فایل با دکمه شروع دانلود
- پشتیبانی از Document، ویدئو، عکس، صوت، ویس، GIF، ویدئوی گرد و استیکر
- حذف خودکار فایل و متادیتا پس از انقضا
- ذخیره پایدار متادیتا در SQLite
- بدون محدودیت حجم داخلی (مناسب فایل‌های چند گیگابایتی)
- امکان محدود کردن ربات به شناسه‌های کاربری مشخص
- هدر دانلود صحیح برای نام فایل‌های فارسی
- Health check در مسیر `/health`
- اجرای آسان با Docker و reverse proxy

## راه‌اندازی سریع روی Ubuntu/Debian

### نصب خودکار با صفحه وب

سیستم‌عامل پشتیبانی‌شده: Ubuntu 22.04 یا جدیدتر، یا Debian 12 و جدیدتر.

پس از کپی پروژه روی سرور، فقط این دستور را اجرا کنید:

```bash
sudo bash install.sh
```

اسکریپت پیش‌نیازها شامل Docker، Nginx و Certbot را نصب می‌کند و سپس یک لینک دارای کد یک‌بارمصرف در ترمینال نشان می‌دهد. لینک را در مرورگر باز کنید و پنج مرحله را انجام دهید:

1. بررسی پیش‌نیازهای سرور
2. ورود توکن ربات، API ID و API Hash
3. ورود دامنه، زمان نگهداری و کاربران مجاز
4. تأیید تنظیمات
5. نصب Docker، تنظیم Nginx و دریافت HTTPS

پورت `9090` باید هنگام نصب در فایروال سرور در دسترس IP خودتان باشد. پس از اتمام نصب، با `Ctrl+C` صفحه نصب را ببندید و پورت 9090 را در فایروال ببندید. فایل `.env` با دسترسی فقط root ذخیره می‌شود و مقادیر محرمانه در گزارش نصب چاپ نمی‌شوند.

### نصب دستی

1. در `@BotFather` یک ربات بسازید و توکن آن را بگیرید.
2. در `my.telegram.org/apps` یک `API_ID` و `API_HASH` بگیرید. این دو با توکن ربات متفاوت‌اند.
3. یک دامنه یا زیردامنه مثل `download.example.com` را به IP سرور وصل کنید.
4. Docker و افزونه Compose را نصب کنید، سپس پروژه را روی سرور کپی کنید.
5. تنظیمات را بسازید:

```bash
cp .env.example .env
nano .env
```

مقادیر `BOT_TOKEN`، `PUBLIC_BASE_URL`، `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را تغییر دهید.

اگر این ربات قبلاً با API ابری تلگرام فعال بوده است، فقط یک بار پیش از انتقال، متد `logOut` تلگرام را برای آن فراخوانی کنید. سپس:

```bash
docker compose up -d --build
docker compose logs -f
```

پوشه `./data` روی میزبان نگه داشته می‌شود؛ با راه‌اندازی مجدد کانتینر فایل‌ها از بین نمی‌روند.

## HTTPS با Nginx

پورت برنامه فقط روی localhost منتشر می‌شود. نمونه تنظیم Nginx:

```nginx
server {
    listen 80;
    server_name download.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

بعد از فعال‌کردن سایت، گواهی رایگان TLS بگیرید:

```bash
sudo certbot --nginx -d download.example.com
```

مقدار `PUBLIC_BASE_URL` باید دقیقاً `https://download.example.com` باشد.

## تنظیمات

| متغیر | کاربرد | پیش‌فرض |
|---|---|---|
| `BOT_TOKEN` | توکن BotFather | الزامی |
| `PUBLIC_BASE_URL` | آدرس عمومی HTTPS | الزامی |
| `FILE_TTL_HOURS` | عمر فایل و لینک | `24` ساعت |
| `MAX_FILE_SIZE_MB` | سقف داخلی؛ صفر یعنی نامحدود | `0` |
| `DATA_DIR` | مسیر داده | `/app/data` |
| `CLEANUP_INTERVAL_SECONDS` | فاصله پاک‌سازی | `300` ثانیه |
| `ALLOWED_USER_IDS` | شناسه‌ها با کاما | خالی = عمومی |

برای پیدا کردن شناسه عددی خود می‌توانید به ربات‌های معتبر نمایش‌دهنده User ID پیام بدهید. برای ربات خصوصی، مقدار نمونه `123456789,987654321` است.

## فایل‌های چند گیگابایتی

فایل Compose یک Local Telegram Bot API Server هم اجرا می‌کند و مسیر داده آن را به‌صورت مشترک و فقط‌خواندنی داخل کانتینر ربات قرار می‌دهد. این کار محدودیت دانلود ۲۰ مگابایتی API ابری را حذف می‌کند. سقف داخلی برنامه نیز با `MAX_FILE_SIZE_MB=0` غیرفعال است.

برای یک فایل ۳ گیگابایتی، هنگام پردازش تقریباً دو نسخه روی دیسک وجود دارد: نسخه Local Bot API و نسخه قابل دانلود برنامه. بنابراین دیسک سرور را با حاشیه امن کافی انتخاب کنید. محدودیت نهایی ارسال فایل همچنان تابع نوع حساب و محدودیت‌های خود تلگرام است.

## اجرای بدون Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

## نکات عملیاتی

- برای فایل‌های چند گیگابایتی، از دیسک محلی سریع با فضای کافی استفاده کنید و فضای آزاد را مانیتور کنید.
- لینک تا زمان انقضا برای هر کسی که آن را داشته باشد قابل استفاده است.
- حذف فایل‌ها هر `CLEANUP_INTERVAL_SECONDS` انجام می‌شود؛ بنابراین ممکن است فایل کمی بعد از زمان انقضا از دیسک حذف شود، اما لینک دقیقاً پس از انقضا از کار می‌افتد.
- برای تغییر زمان نگهداری، `FILE_TTL_HOURS` را عوض و سرویس را با `docker compose up -d` بازسازی/راه‌اندازی کنید.
