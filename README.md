# ربات تبدیل فایل تلگرام به لینک دانلود

ربات انواع فایل و رسانه ارسالی در تلگرام را دریافت می‌کند، روی دیسک سرور نگه می‌دارد، یک لینک تصادفی اختصاصی می‌سازد و پس از زمان تعیین‌شده فایل را خودکار حذف می‌کند.

## امکانات

- لینک غیرقابل حدس با توکن تصادفی ۲۵۶ بیتی
- صفحه واسط بررسی مشخصات فایل با دکمه شروع دانلود
- صفحه اختصاصی «لینک منقضی شده» با پاسخ استاندارد HTTP 410
- پنل `/admin` برای تعریف کانال‌ها و ربات‌های مبدأ مجاز
- وضعیت دیسک و سرویس، آمار، فایل‌های اخیر، حذف امن، پاک‌سازی و بکاپ متادیتا در پنل مدیر
- حالت پذیرش انحصاری فایل‌های فورواردشده از منابع مجاز
- نمایش درصد، حجم دریافت‌شده و سرعت انتقال فایل به سرور
- timeout شش‌ساعته و نمایش زمان انتظار برای آماده‌سازی فایل‌های چندگیگابایتی در Local Bot API
- تأیید یا لغو توسط کاربر پیش از آغاز انتقال و مصرف فضای سرور
- پشتیبانی از چند فضای S3، Multipart Upload، انتخاب هوشمند و Presigned Download
- پنل امن `/manage/` با PBKDF2، نشست Secure، CSRF، rate limit و تنظیمات رمز‌شده Fernet
- پشتیبانی از Document، ویدئو، عکس، صوت، ویس، GIF، ویدئوی گرد و استیکر
- حذف خودکار فایل و متادیتا پس از انقضا
- ذخیره پایدار متادیتا در SQLite
- بدون محدودیت حجم داخلی (مناسب فایل‌های چند گیگابایتی)
- امکان محدود کردن ربات به شناسه‌های کاربری مشخص
- هدر دانلود صحیح برای نام فایل‌های فارسی
- Health check در مسیر `/health`
- اجرای آسان با Docker و reverse proxy

## راه‌اندازی سریع روی Ubuntu/Debian

### نصب خودکار با صفحه وب

سیستم‌عامل پشتیبانی‌شده: Ubuntu 22.04 یا جدیدتر، یا Debian 12 و جدیدتر.

پس از کپی پروژه روی سرور، فقط این دستور را اجرا کنید:

```bash
sudo bash install.sh
```

اسکریپت پیش‌نیازها شامل Docker، Nginx و Certbot را نصب می‌کند و سپس یک لینک دارای کد یک‌بارمصرف در ترمینال نشان می‌دهد. لینک را در مرورگر باز کنید و پنج مرحله را انجام دهید:

1. بررسی پیش‌نیازهای سرور
2. ورود توکن ربات، API ID و API Hash
3. ورود دامنه، زمان نگهداری و کاربران مجاز
4. تأیید تنظیمات
5. نصب Docker، تنظیم Nginx و دریافت HTTPS

پورت `9090` باید هنگام نصب در فایروال سرور در دسترس IP خودتان باشد. پس از اتمام نصب، با `Ctrl+C` صفحه نصب را ببندید و پورت 9090 را در فایروال ببندید. فایل `.env` با دسترسی فقط root ذخیره می‌شود و مقادیر محرمانه در گزارش نصب چاپ نمی‌شوند.

### نصب دستی

1. در `@BotFather` یک ربات بسازید و توکن آن را بگیرید.
2. در `my.telegram.org/apps` یک `API_ID` و `API_HASH` بگیرید. این دو با توکن ربات متفاوت‌اند.
3. یک دامنه یا زیردامنه مثل `download.example.com` را به IP سرور وصل کنید.
4. Docker و افزونه Compose را نصب کنید، سپس پروژه را روی سرور کپی کنید.
5. تنظیمات را بسازید:

```bash
cp .env.example .env
nano .env
```

مقادیر `BOT_TOKEN`، `PUBLIC_BASE_URL`، `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را تغییر دهید.

اگر این ربات قبلاً با API ابری تلگرام فعال بوده است، فقط یک بار پیش از انتقال، متد `logOut` تلگرام را برای آن فراخوانی کنید. سپس:

```bash
docker compose up -d --build
docker compose logs -f
```

پوشه `./data` روی میزبان نگه داشته می‌شود؛ با راه‌اندازی مجدد کانتینر فایل‌ها از بین نمی‌روند.

## HTTPS با Nginx

پورت برنامه فقط روی localhost منتشر می‌شود. نمونه تنظیم Nginx:

```nginx
server {
    listen 80;
    server_name download.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

بعد از فعال‌کردن سایت، گواهی رایگان TLS بگیرید:

```bash
sudo certbot --nginx -d download.example.com
```

مقدار `PUBLIC_BASE_URL` باید دقیقاً `https://download.example.com` باشد.

## تنظیمات

| متغیر | کاربرد | پیش‌فرض |
|---|---|---|
| `BOT_TOKEN` | توکن BotFather | الزامی |
| `PUBLIC_BASE_URL` | آدرس عمومی HTTPS | الزامی |
| `FILE_TTL_HOURS` | عمر فایل و لینک | `24` ساعت |
| `MAX_FILE_SIZE_MB` | سقف داخلی؛ صفر یعنی نامحدود | `0` |
| `DATA_DIR` | مسیر داده | `/app/data` |
| `CLEANUP_INTERVAL_SECONDS` | فاصله پاک‌سازی | `300` ثانیه |
| `ALLOWED_USER_IDS` | شناسه‌ها با کاما | خالی = عمومی |
| `ADMIN_USER_ID` | شناسه عددی تنها مدیر پنل | `0` = بدون مدیر |
| `FORWARD_ONLY` | پذیرش فقط از منابع تعریف‌شده در پنل | `false` |
| `ADMIN_WEB_PASSWORD_HASH` | هش رمز پنل `/manage/` | خالی = پنل غیرفعال |
| `STORAGE_BACKEND` | وضعیت اولیه `local` یا `s3` | `local` |
| `S3_BACKENDS_JSON` | فهرست اولیه backendهای سازگار با S3 | `[]` |

## پنل امن فضای ذخیره‌سازی

پنل در `https://YOUR-DOMAIN/manage/` قرار دارد. در نصب جدید، رمز آن در Wizard دریافت و فقط هش PBKDF2 ذخیره می‌شود. برای نصب موجود، هش بسازید:

پنل مدیریت به‌صورت چندبخشی ارائه می‌شود:

- داشبورد زنده برای فایل‌ها، حجم فعال، صف replication، سلامت S3 و دیسک
- صفحه فایل‌ها برای مشاهده محل اصلی، تعداد replica، انقضا، لینک و حذف کامل
- صفحه فضاها برای افزودن S3، ظرفیت، رزرو، اولویت، فعال‌سازی و مهاجرت
- صفحه صف انتقال برای مشاهده تلاش‌ها، خطاها و اجرای دوباره کارها
- صفحه سیستم برای uptime پردازش، load، مصرف دیسک و وضعیت backendها
- صفحه رویدادها برای Audit Log عملیات معتبر مدیر بدون ثبت رمز و کلید
- صفحه تنظیمات برای تغییر رمز، خروج سایر نشست‌ها، ساخت و دانلود بکاپ SQLite

برنامه هر ۲۴ ساعت یک snapshot خودکار SQLite می‌سازد و هفت نسخه آخر را در `data/backups/` نگه می‌دارد. بکاپ دستی پنل نیز ده نسخه آخر را حفظ می‌کند. اگر مصرف دیسک به ۹۰٪ برسد یا یک backend فعال ناسالم شود، ربات یک هشدار به `ADMIN_USER_ID` ارسال می‌کند.

در مرحله «دامنه و دسترسی» نصب‌کننده، رمز پنل و تکرار آن دریافت می‌شود. رمز باید حداقل ۱۲ کاراکتر باشد؛ تطابق دو ورودی هم در مرورگر و هم روی سرور کنترل می‌شود و متن اصلی رمز در `.env` نوشته نخواهد شد.

```bash
python3 scripts/hash_password.py
```

خط خروجی را عیناً با کوتیشن تکی در `.env` قرار دهید؛ علامت‌های `$` بخشی از هش هستند و نباید حذف یا توسط Compose جایگزین شوند. سپس کانتینر را بازسازی کنید. پنل نشست ۳۰ دقیقه‌ای Secure/HttpOnly، CSRF، محدودیت پنج ورود ناموفق در ۱۵ دقیقه و تنظیمات رمز‌شده Fernet دارد. افزودن S3 تنها بعد از `HeadBucket` موفق انجام می‌شود و اولین backend موفق، ذخیره‌سازی فایل‌های جدید را روی S3 فعال می‌کند.

در همین پنل می‌توانید تعداد کل نسخه‌های هر فایل را از ۱ تا ۵ تعیین کنید. ربات نسخه اصلی و replicaها را روی سرویس‌های متفاوت می‌گذارد و هنگام دانلود، فضای سالم‌تر را انتخاب می‌کند. مقدار بالاتر از تعداد فضاهای ثبت‌شده، عملاً به تعداد فضاهای موجود محدود می‌شود.

برای هر فضای ثبت‌شده می‌توان اولویت آپلود را تغییر داد یا ورود فایل جدید به آن را موقتاً غیرفعال کرد. غیرفعال‌سازی، فایل‌های موجود را حذف نمی‌کند و در صورت نیاز هنوز می‌توان از آن نسخه برای دانلود استفاده کرد. حذف تنظیمات یک فضا فقط وقتی مجاز است که هیچ فایل اصلی یا replica به آن ارجاع نداشته باشد.

برای هر backend می‌توان «ظرفیت قابل استفاده» و «فضای رزرو» را بر حسب GB تعیین کرد. مقدار صفر یعنی نامحدود. مصرف از فایل‌های اصلی، replicaهای ساخته‌شده و کارهای replication در صف محاسبه می‌شود. مقصدی که فایل جدید به‌همراه فضای رزرو در آن جا نشود حذف و میان گزینه‌های باقی‌مانده، فضای کم‌مصرف‌تر با درنظرگرفتن سلامت، اولویت و تأخیر انتخاب می‌شود.

ساخت replica در صف پایدار SQLite انجام می‌شود. بعد از ثبت نسخه اصلی، لینک فوراً قابل استفاده است و worker نسخه‌های دیگر را در پس‌زمینه می‌سازد. کار ناموفق با backoff نمایی دوباره اجرا می‌شود و بعد از restart نیز از همان صف ادامه پیدا می‌کند. فایل موقت تا تکمیل تمام replicaهای آن فایل حفظ و سپس پاک می‌شود.

پیش از صدور لینک موقت، ربات با `HeadObject` وجود واقعی فایل را بررسی می‌کند. اگر object اصلی حذف یا فضای مربوطه خراب شده باشد، replica بعدی بررسی و انتخاب می‌شود. بنابراین صرفاً سالم‌بودن Bucket برای failover کافی فرض نمی‌شود.

دکمه «شروع انتقال امن به S3» فایل‌های فعال قدیمی روی دیسک را نیز منتقل می‌کند. برای هر فایل ابتدا آپلود و replicaها ساخته و رکورد دیتابیس ثبت می‌شود؛ سپس نسخه محلی حذف خواهد شد. وضعیت و تعداد موفق/ناموفق در همان صفحه نمایش داده می‌شود. این عملیات در پس‌زمینه انجام می‌شود، بنابراین صفحه را می‌توان بست؛ اما تا پایان مهاجرت کانتینر را restart نکنید.

```bash
docker compose up -d --build --force-recreate file-link-bot
```

فایل `data/config.key` برای بازیابی تنظیمات رمز‌شده ضروری است و در بکاپ کامل قرار می‌گیرد. آن را عمومی نکنید.

تنظیم اولیه S3 که Wizard در `.env` می‌نویسد، در اولین اجرا خودکار به فایل رمز‌شده منتقل می‌شود. پس از اطمینان از اجرای موفق، می‌توانید مقدار `S3_BACKENDS_JSON` را در `.env` به `[]` تغییر دهید و سرویس را بازسازی کنید؛ نسخه رمز‌شده باقی می‌ماند.

## پنل مدیریت منابع فوروارد

`ADMIN_USER_ID` را روی شناسه عددی مدیر تنظیم کنید. مقدار `FORWARD_ONLY` فقط وضعیت اولیه در اولین اجراست و پس از آن مدیر می‌تواند محدودیت را از پنل روشن یا خاموش کند. مدیر `/admin` را برای ربات ارسال می‌کند، «افزودن مبدأ مجاز» را می‌زند و یک فایل را مستقیماً از کانال یا ربات موردنظر فوروارد می‌کند. شناسه مبدأ و وضعیت محدودیت در SQLite ذخیره می‌شوند و با restart از بین نمی‌روند. در حالت فعال، فایل عادی و فایل فورواردشده از هر منبع دیگری رد خواهد شد.

فرمان‌های متنی مدیر: `/status` برای وضعیت دیسک و سرویس، `/stats` برای آمار، `/cleanup` برای حذف فوری موارد منقضی و `/backup` برای دریافت snapshot سازگار SQLite. بکاپ تلگرامی شامل فایل‌های اصلی و `.env` نیست؛ برای مهاجرت کامل همچنان از `scripts/backup.sh` استفاده کنید.

برای پیدا کردن شناسه عددی خود می‌توانید به ربات‌های معتبر نمایش‌دهنده User ID پیام بدهید. برای ربات خصوصی، مقدار نمونه `123456789,987654321` است.

## فایل‌های چند گیگابایتی

فایل Compose یک Local Telegram Bot API Server هم اجرا می‌کند و مسیر داده آن را به‌صورت مشترک و فقط‌خواندنی داخل کانتینر ربات قرار می‌دهد. این کار محدودیت دانلود ۲۰ مگابایتی API ابری را حذف می‌کند. سقف داخلی برنامه نیز با `MAX_FILE_SIZE_MB=0` غیرفعال است.

برای یک فایل ۳ گیگابایتی، هنگام پردازش تقریباً دو نسخه روی دیسک وجود دارد: نسخه Local Bot API و نسخه قابل دانلود برنامه. بنابراین دیسک سرور را با حاشیه امن کافی انتخاب کنید. محدودیت نهایی ارسال فایل همچنان تابع نوع حساب و محدودیت‌های خود تلگرام است.

## اجرای بدون Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

اجرای آزمون‌های داخلی:

```bash
python -m unittest discover -s tests -v
```

## نکات عملیاتی

- برای فایل‌های چند گیگابایتی، از دیسک محلی سریع با فضای کافی استفاده کنید و فضای آزاد را مانیتور کنید.
- لینک تا زمان انقضا برای هر کسی که آن را داشته باشد قابل استفاده است.
- حذف فایل‌ها هر `CLEANUP_INTERVAL_SECONDS` انجام می‌شود؛ بنابراین ممکن است فایل کمی بعد از زمان انقضا از دیسک حذف شود، اما لینک دقیقاً پس از انقضا از کار می‌افتد.
- برای تغییر زمان نگهداری، `FILE_TTL_HOURS` را عوض و سرویس را با `docker compose up -d` بازسازی/راه‌اندازی کنید.

## پایداری بعد از reboot

اگر سرور خاموش باشد ربات نیز در دسترس نیست، اما Docker در نصب خودکار به‌عنوان سرویس سیستم فعال می‌شود و کانتینرها به‌دلیل `restart: unless-stopped` پس از روشن‌شدن سرور خودکار بالا می‌آیند. بررسی وضعیت:

```bash
systemctl status docker
docker compose ps
```

## بکاپ و انتقال به سرور جدید

بکاپ کامل شامل `.env`، دیتابیس SQLite و تمام فایل‌های دانلود است. فایل‌های ویدئویی معمولاً از قبل فشرده‌اند، بنابراین آرشیو بدون فشرده‌سازی ساخته می‌شود تا CPU و زمان هدر نرود:

```bash
sudo ./scripts/backup.sh /var/backups/uploadrobotelemovie full
```

بکاپ سبک فقط شامل تنظیمات و دیتابیس است و خود فایل‌های آپلودشده را ندارد:

```bash
sudo ./scripts/backup.sh /var/backups/uploadrobotelemovie metadata
```

در هر دو حالت checksum نیز ساخته می‌شود. پیش‌فرض، بکاپ‌های قدیمی‌تر از ۷ روز حذف می‌شوند؛ قابل تغییر است:

```bash
sudo BACKUP_RETENTION_DAYS=30 ./scripts/backup.sh /var/backups/uploadrobotelemovie full
```

برای انتقال، فایل `.tar` و `.sha256` را با `scp` یا `rsync` به سرور جدید بفرستید. ابتدا همان مخزن را در سرور جدید clone کنید، سپس:

```bash
cd /opt/uploadrobotelemovie
sudo ./scripts/restore.sh /path/to/uploadrobotelemovie-full-TIMESTAMP.tar
```

اسکریپت checksum را کنترل، سرویس را متوقف، داده فعلی را در پوشه recovery نگهداری و بکاپ را بازیابی می‌کند. به‌دلیل وجود توکن ربات در بکاپ، فایل آرشیو باید با دسترسی محدود نگهداری و از کانال امن منتقل شود.
